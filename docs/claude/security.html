Security & Data Protection

Threat model for a shop till: theft, insider fraud, power loss, malware, lost cloud keys

2. Authentication & authorisation

  • Touch PIN login (4-6 digits) per user; stored as argon2id hash; lockout after 5 tries (5 min, then owner reset).
  • Roles: owner (all), cashier (sell, hold, view own shift). Permission matrix enforced in Rust commands, never only in UI.
  • Auto-lock after N minutes idle; fast user switch.
  • Sensitive actions requiring owner PIN: void bill, return, price override, discount > X%, stock adjust, petty cash, edit credit, close shift variance, backup restore, settings.
  • Cloud: owner dashboard uses Supabase Auth (email + password + MFA/TOTP).

3. Data protection

  • At rest: SQLCipher AES-256; key generated at install, wrapped with DPAPI; recovery key printed once for the owner.
  • In transit: TLS 1.2+ only to Supabase; certificate validation on; no HTTP.
  • Backups: AES-256-GCM encrypted before upload; passphrase held by owner, not in Supabase.
  • No card data stored (PCI scope avoided): card/QR payments recorded as method + amount only.
  • Logs never contain PIN, tokens, full phone numbers.

4. Supabase security checklist

  • RLS enabled on every table; policies tested with a negative test per table.
  • Device identity: one Supabase Auth user per device with custom claim shop_id; short-lived JWT, refresh token stored in DPAPI.
  • Device role cannot DELETE or UPDATE immutable tables (sale, payment, stock_movement, audit_log).
  • Storage bucket backups private; per-shop folder policy.
  • Run Supabase security advisors after each migration; enable daily PITR/backup if plan allows.
  • Rotate keys if a PC is lost; revoke device from dashboard (remote kill).

5. Audit & integrity

  • audit_log is append-only; each row stores prev_hash + hash (SHA-256) to detect tampering.
  • Bill numbers are gap-free per day; voids keep the number.
  • Z-report prints totals + last audit hash.

6. Application hardening

  • Tauri allowlist: minimal commands, no shell/fs access from the webview; strict CSP (default-src 'self').
  • All SQL parameterised; input validated in Rust (lengths, ranges, integer cents).
  • Dependency pinning + cargo audit / npm audit in CI; lockfiles committed.
  • Secrets never committed; .env ignored; build secrets in CI vault.
  • Crash reports opt-in, scrubbed.

7. Operational security

  • Windows: BitLocker (if TPM) or at least strong user password; separate admin account; auto-updates scheduled outside trading hours.
  • Kiosk mode: app auto-starts, shell hidden, Alt-Tab/Win key restricted for cashier account.
  • Network: shop WiFi WPA2/3, router admin password changed; PC firewall inbound deny.
  • Monthly restore drill on a spare machine.
  • Incident plan: lost PC → revoke device in Supabase, rotate keys, restore on new PC from backup.

8. Residual risks to accept or decide

Owner PIN shared with staff defeats approvals; no hardware token for a small shop. If the owner forgets the backup passphrase, cloud backups are unrecoverable — print and store it safely.
