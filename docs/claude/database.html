Database Design

SQLite (local, source of truth) mirrored to Supabase Postgres

Conventions

  • PK: id TEXT UUID v7 (Postgres: uuid).
  • Money: integer cents (LKR × 100). Quantity: integer in smallest unit (pcs, or grams for weighed items → qty_milli = thousandths).
  • Every table: created_at, updated_at, deleted_at (soft delete), device_id.
  • Sales, payments, stock movements are immutable; corrections via reversing records.

Key rules

  • On-hand stock = SUM(stock_movement.qty_milli); cached in product_stock view/table updated in same transaction.
  • Credit balance = SUM(credit_ledger.amount_cents).
  • Bill number: YYMMDD-NNN, generated inside the sale transaction.
  • Price changes never alter old sales (snapshot columns).
  • Negative stock allowed with warning (shops often sell before recording purchases) — configurable.

Starter DDL (excerpt)

CREATE TABLE product (
  id TEXT PRIMARY KEY, sku TEXT UNIQUE, name_si TEXT NOT NULL, name_en TEXT,
  category_id TEXT REFERENCES category(id), unit TEXT NOT NULL DEFAULT 'pcs',
  is_weighed INTEGER NOT NULL DEFAULT 0,
  cost_cents INTEGER NOT NULL DEFAULT 0 CHECK (cost_cents >= 0),
  price_cents INTEGER NOT NULL CHECK (price_cents >= 0),
  tax_rate_bp INTEGER NOT NULL DEFAULT 0, reorder_level INTEGER DEFAULT 0,
  active INTEGER NOT NULL DEFAULT 1,
  created_at TEXT NOT NULL, updated_at TEXT NOT NULL, deleted_at TEXT, device_id TEXT
);
CREATE TABLE stock_movement (
  id TEXT PRIMARY KEY, product_id TEXT NOT NULL REFERENCES product(id),
  qty_milli INTEGER NOT NULL, type TEXT NOT NULL, ref_id TEXT, note TEXT,
  user_id TEXT NOT NULL, at TEXT NOT NULL
);
CREATE INDEX ix_sm_product ON stock_movement(product_id);
CREATE INDEX ix_sale_at ON sale(at);
CREATE UNIQUE INDEX ux_barcode ON product_barcode(barcode);

Supabase side

  • Same tables plus shop_id column on each; RLS on every table: shop_id = (auth.jwt()->>'shop_id')::uuid.
  • Device writes via role pos_device (insert/upsert only, no delete). Owner dashboard role is read-only.
  • Views for dashboard: v_daily_sales, v_top_items, v_credit_outstanding, v_low_stock.
  • Migrations managed as files in supabase/migrations; run get_advisors after each change.

Search (Sinhala)

Use SQLite FTS5 over name_si + name_en + barcode + sku. Also store a Singlish/transliterated keyword column so cashiers can type English letters to find Sinhala names.
